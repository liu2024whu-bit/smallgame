# 实际取物 · V2.9.5

用户要求机关解开后，物品可以留在抽屉、盒内、新出现的位置，实际拿起后再进入道具栏；也可以通过打开某个地方表现结果。该要求作为跨关的库存规则落实，不能只在个别界面做“拿起”动画而后台已经自动发物。

## 当前实现

库存只来自一份`collected`。解开机关只改变机关和可领取来源；`pickup`必须验证来源真的解开、物件属于已知来源、此前没有拿过。没有另存一份“待领取进度”。未拿走或只拿了一件可以离开再来，读取后保持原来的区别。

试印的透片留在真实抽屉里；纸稿移到盒前的落纸处，避免挡住取物，透片平放在抽屉底面。两面的云打开两扇侧袋，圆镜和摇柄可分别点取，拿走后袋内变空。近景和房间小景共用领取状态。飞向手边的短动作仅负责呈现，减少动态时直接收好，不延迟库存生效。

其余有工具奖励的关卡改为可领取结果；独立的摆放位置和美术表现仍随P7、P8、P10、P11、P12、P19、P20逐关打磨，不能将临时的共用结果呈现算成每关的美术完成。收藏柜的小物和成就仍在P29/P30的整体验收范围。没有工具奖励的机关可以直接打开新场景或改变现场，不强行增加领取动作。

## 比较与清理

旧版根据`solved.flatMap(rewards)`自动生成库存，现已删除，领取后统一写入`collected`。第一轮只把抽屉物件改为按钮，实际命中检查发现纸稿挡住中心；第二轮移动纸稿、把透片放平，核对鼠标、触摸与键盘均可拿到。

移除旧的奖励文字行样式和五处重复的测试通关函数。旧存档迁移仍保留：修订9以前的合法完成确实已经自动获得奖励，因此只给通过依赖和规则验证的旧完成补回原物件；修订10不制造未领取物品。该兼容分支不是过期代码，仍有实际验证。

## 验证边界

四项新增规则/存档测试覆盖未领取重读、双物件独立领取、提前/伪造领取及旧自动库存兼容。鼠标与原生触摸分别核对1440、390、320宽的试印、云景与书架领取；还有减少动态、来源消失、飞行动画收尾和后台文字状态。

187项测试通过；26机关实际控件路线逐项解开并实际点取工具到生日结尾。全新正式游戏完成试印后导出未领取存档，在另一空上下文读取并拿起；云景只取摇柄再导出/读回，圆镜仍留在侧袋；最后取齐、进入光影机关，再次导出/读回时不重生物件。三份测试存档已删除。257个检阅状态在320/390/1440宽均检查，91个图片引用（83份不同资源）全部解码；后台搜索/跳转/实际输入、文字导出和正式/备份存档隔离检查通过。

[对照与点取演示](../review/pickups/index.html)保留旧自动入栏、第一轮遮挡问题和改进后的图像。录像只演示已解开抽屉里的原生点取，明确标注预置状态，不用它证明完整解谜体验。

本次只完成库存规则与前两处具体来源的调整。台灯、书桌与光影机关按新反馈重开协调：不是回贴旧图，要连同体量、摆放、光照、支架和道具考虑；硬边光路与投影仍待手绘质感的进一步处理。P6已保存旧版实操证据和两份美术试稿，尚未接入运行代码或算完成。
